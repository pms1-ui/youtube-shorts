# 시행착오 · 오류 재발방지 노트 (전 채널 공통, 항상 준수)

이 프로젝트에서 실제로 겪은 오류와 해결책. **같은 실수를 반복하지 않는다.**
새로운 시행착오가 생기면 여기에 계속 추가한다.

---

## A. 렌더 길이 / 타이밍 (가장 중요)

- **A1. 영상 길이는 "녹음 오디오 길이"가 기준이다.**
  녹음이 있으면 `StoryScript.audioDurationSec`를 채우고, `totalSeconds()`는 그 값을 그대로 반환한다.
  인트로 길이나 outro, +2.5초 같은 여유를 **더하지 않는다.** (한때 37.28초로 늘어난 사고의 원인)
- **A2. 인트로를 앞에 따로 더하지 않는다.**
  인트로 문장("… 근황")은 **녹음 맨 앞에 이미 포함**돼 있다. 따라서 자막/효과음/컷에
  인트로 길이만큼 오프셋(+introDur)을 주면 안 된다. 전사 타임코드를 **그대로** 쓴다(OFFSET=0).
- **A3. 자막·효과음 타이밍은 전사(녹음) 타임코드에 맞춘다.**
  내가 임의로 start 초를 찍지 않는다. `narration.generated.ts`의 타임코드가 기준.
- **A4. 인트로 낭독 구간에는 하단 자막을 띄우지 않는다.**
  인트로 문장을 읽는 동안(0 ~ `intro.durationSec`) 본문 자막이 겹치면 안 된다.
  - script: 첫 본문 비트 start를 인트로가 끝나는 실제 시각으로(전사 확인).
  - 구조적 방지: `HeadlineShorts`가 `startFrame >= introDur` 인 자막 비트만 렌더(필터 내장).
  - `intro.durationSec`은 전사에서 인트로 문장이 실제로 끝나는 시각에 맞춘다.

## B. Remotion 렌더 옵션 충돌

- **B1. 전역 `Config.setCrf()` 금지.** CRF는 코덱마다 다르게 동작해서 prores/mp3와 충돌
  ("The 'prores' codec does not support the --crf option"). CRF는 **mp4 렌더 명령에만** `--crf=18`로 붙인다.
- **B2. 투명(알파) 영상은 `--image-format=png` 필수.** jpeg면
  "Pixel format was set to 'yuva…' but the image format is not PNG" 에러.
  자막 mov(prores 4444, `--pixel-format=yuva444p10le`)는 반드시 `--image-format=png` 동반.
- **B3. 코덱별 출력**: main=mp4(h264,+crf), 자막=mov(prores 4444, png, 알파), 효과음=mp3.

## C. 파일 잠금 / 렌더 실행

- **C1. mp4 EPERM rename 에러**: 기존 출력 파일이 재생기/미리보기에 잠겨 있으면 렌더 마지막
  rename이 실패한다. 렌더 전 기존 `out/<...>.mp4`와 `*.remotion-in-progress`를 지운다.
  삭제가 잠기면 새 파일명(_v2 등)으로 렌더한 뒤 잠금 풀리면 정식명으로 교체.
- **C2. `execute_pwsh`가 긴 렌더 도중 조기 반환**한다(exit 1처럼 보여도 실제로는 진행 중).
  → 콘솔 출력만 믿지 말고 **결과 파일의 존재/크기/수정시각을 폴링**해 완료를 확인한다.
- **C3. 진행상황을 자주 공유**한다(프레임 카운트 등). 오래 걸리면 중간 상태를 보고한다.
- **C4. 결과물은 편별 하위 폴더**(`out/<채널>/<YYMMDD>_<순번>/`)에 5종이 모인다. 새 편은 `render.mjs ... --new`(순번+1). 파일 이동/정리 시 사용자가 편집기(프리미어)·재생기로 mp4/mov를 열어두면 "다른 프로세스에서 사용 중" 에러가 난다 → 사용자에게 닫아달라고 요청한 뒤 다시 이동. `_final.mp4`류는 **사용자 편집 최종본**이므로 건드리지 않는다.

## D. 콘솔 / 셸 (Windows PowerShell)

- **D1. 한글 파일명이 콘솔에서 깨져 보인다**(`??섏옣誘쇨뎅`). 파일 내용은 정상.
  검증은 **파일 존재/크기/시각**으로 한다(깨진 콘솔 문자열로 판단 X).
- **D2. `/dev/null` 쓰지 말 것**(Windows). 출력 버리려면 `*>$null` 또는 로그파일.
- **D3. 명령 체이닝은 `;`**, `&&` 아님.

## E. Whisper 전사 (STT)

- **E1. 전사는 `whisper.cpp/main.exe` 직접 호출**이 안정적(`-m 모델 -l ko -f wav -ml 16 -sow -oj -of out`).
  라이브러리 래퍼가 인자 형식으로 실패한 적 있음.
- **E2. `ffprobe`는 이 remotion ffmpeg 번들에서 불안정** → 오디오 길이는 전사 JSON의
  마지막 offset으로 계산(별도 ffprobe 호출 금지).
- **E3. whisper 입력은 16kHz 모노 wav**로 변환 후 넣는다.
- **E4. STT 오인식은 당연히 생긴다**(예: "영포티"→"040", "천정부지"→"전정부지").
  → **타임코드만 신뢰**하고, 자막 텍스트는 **원본 대본으로 교정**해서 script에 직접 둔다.
- **E5. `audio/` 자동탐색 시 `_`·`test` 접두 파일(임시 산출물) 제외.** 입력·출력 wav가 같은 경로면 ffmpeg 실패.
- **E6. 긴 녹음에서 특정 구간이 뭉개질 수 있다.** whisper가 전체 파일을 전사할 때 중간 10여 초를 한두 조각으로만 잡아, 자막에 긴 공백이 생기는 경우가 있다(예: 힌두푸쉬업 24~37초). → **그 구간만 ffmpeg로 잘라(`-ss A -to B`) 재전사**하면 정확한 텍스트·타임코드가 복원된다. 잘라낸 구간은 상대시각이므로 **잘라낸 시작 초(A)를 더해 절대시각으로 환산**해 script에 넣는다. 임시 wav/json은 작업 후 삭제.

## F. 효과음 파일

- **F1. 효과음 앞 무음 제거**: 화면 전환에 딱 맞으려면 앞 무음이 없어야 한다.
  `silencedetect`(-40dB)로 앞 무음을 측정하고, 있으면 `-ss`로 잘라낸다
  (이 ffmpeg 빌드엔 `silenceremove` 필터 없음 → `-ss` 트림 사용). 원본은 백업.
- **F2. 볼륨 보정**: 특정 효과음이 작으면 `volume=NdB`로 키워 파일 자체를 교체(예: 뽁 +8dB).
- **F3. 새 효과음 추가 시 위 F1(무음)·F2(볼륨)를 점검**한다.

## G. 레이아웃 / 출력물 분리 (headline)

- **G1. 상단/중앙/하단은 독립 영역.** 자막은 사진에 묶지 않고 하단 블록에 고정.
- **G2. 편집용 3분할 출력**:
  - `_main.mp4` = 상단바 + 인트로 + 빈 중앙(검정) + 하단 검정바. **소리 없음, 사진 없음**(사진은 편집에서 직접).
  - `_sub.mov` = 자막 **흰 글자만**(박스·외곽선 없음, 투명 배경). main의 하단 검정바 위에 얹힘 → 배경 침범 없음.
  - `_sfx.mp3` = 효과음만.
  - 원본 내레이션 오디오는 편집(프리미어)에서 직접 얹는다(렌더에 안 넣음).
- **G3. 자막 글자는 흰색**(까만 배경 위). 외곽선 불필요.
- **G4. 레이아웃 상수(현재값, `HeadlineShorts.tsx`)**: 자막을 한 줄 위로 올린 배치.
  - 중앙 미디어: `MEDIA_TOP=560`, `MEDIA_HEIGHT=790` → 미디어 하단 = 1350.
  - 하단 자막 블록: `BOTTOM_BLOCK.top=1390`, `height=300`(자막 글자 + 검정 바 공용).
  - ★ 자막 위치를 조정할 땐 **미디어 하단(MEDIA_TOP+MEDIA_HEIGHT)과 BOTTOM_BLOCK.top이 겹치지 않게** 둘을 같이 움직인다. 자막 글자(NarrationLine)와 검정 바(BottomBar)는 둘 다 BOTTOM_BLOCK.top 기준이라 이 값 하나만 바꾸면 함께 이동한다.
- **G5. 상단 헤드라인은 폰트 자동 축소(fitFontSize)로 항상 한 줄 유지.** `HeadlineShorts.tsx`에 `fitFontSize()`가 있어, 헤드라인 한 줄이 가용 폭(1020px)을 넘치면 폰트를 자동으로 줄이고 `whiteSpace:nowrap`로 강제 한 줄 유지한다. 짧은 헤드라인(대환장민국 등)은 영향 없음. → 헤드라인 문구가 길어도 "이/유"처럼 두 줄로 깨지지 않는다. 그래도 권장 글자수(line1 8~10자, line2 6~9자)는 지키는 게 크기 유지에 좋다.

## H. 툴 사용

- **H1. `todo_list`의 tasks는 배열**로. 문자열 안에 깨진 유니코드 이스케이프가 들어가면 스키마 오류.
- **H2. 진행상황·설명은 항상 한글.**
- **H3. ★ "call"만 반복 출력되는 도구호출 오류 방지.** 렌더/전사처럼 오래 걸리는 작업을 기다릴 때, 빈 도구 호출을 연달아 쏟아내면 화면에 `call`만 수십 줄 찍히는 오류가 난다. 원인은 "완료를 기다린다"며 무의미한 호출을 반복하는 것.
  - 대기할 땐 **`Start-Sleep` 한 번 + 결과 확인(파일 존재/크기/시각 폴링) 한 번**으로 끝낸다. 아직이면 한 번 더 sleep+확인. **절대 빈 호출을 연속으로 남발하지 않는다.**
  - 한 응답에서 같은 목적의 도구 호출을 3번 넘게 반복하지 않는다. 진행 중이면 사용자에게 상태를 알리고 멈춘다.
  - 백그라운드 프로세스는 `list_processes`로 상태를 보고, 끝난 것은 `stop`으로 정리한다(좀비 프로세스 누적 방지).
